Cheat sheet

Policy evaluation in 8 steps

For a request inside a single account. For cross-account access, the identity side and the resource side must both allow it.

  1. Any applicable explicit Deny in any policy wins immediately. That includes identity, resource, boundary, session, SCP and RCP.
  2. SCPs on the principal's account and every OU above it must allow the action (SCPs never apply to the management account or service-linked roles).
  3. RCPs on the resource's account and its OUs must allow the action on supported resources (S3, STS, KMS, SQS, Secrets Manager and more).
  4. A resource-based policy that names the principal can grant access on its own in the same account. If it names an IAM user ARN or a role session ARN, implicit denies in boundaries and session policies don't limit it. If it names a role ARN, they do.
  5. Permissions boundaries cap what identity policies can grant.
  6. Session policies (passed on AssumeRole or federation) cap the session further.
  7. Identity-based policies must contain an Allow.
  8. Nothing allowed it? Then it's an implicit deny. Declarative policies sit outside this flow: they set the service's configuration, so the API refuses a non-compliant change before any authorization decision.
Mnemonic

"Deny, Org, Resource, Boundary, Session, Identity." If any gate says no, the answer is no. A resource policy can open its own door, but it can't get past the Org gates.

Query pack

Threat-hunting SQL

For CloudTrail logs in Athena. Adjust table names to your setup (Security Lake OCSF tables use api.operation, actor.user.uid and similar).

SELECT eventtime, useridentity.arn, sourceipaddress,
       json_extract_scalar(additionaleventdata, '$.MFAUsed') AS mfa
FROM cloudtrail_logs
WHERE eventname = 'ConsoleLogin'
  AND json_extract_scalar(additionaleventdata, '$.MFAUsed') = 'No'
  AND eventtime > to_iso8601(current_timestamp - interval '7' day)
ORDER BY eventtime DESC;
SELECT eventtime, useridentity.arn AS actor,
       json_extract_scalar(requestparameters, '$.userName') AS target_user,
       sourceipaddress, useragent
FROM cloudtrail_logs
WHERE eventname IN ('CreateAccessKey', 'CreateLoginProfile', 'UpdateLoginProfile')
ORDER BY eventtime DESC
LIMIT 100;
SELECT eventtime, eventsource, eventname, useridentity.arn, sourceipaddress, errorcode
FROM cloudtrail_logs
WHERE eventname IN ('StopLogging','DeleteTrail','UpdateTrail','PutEventSelectors',
                    'DeleteDetector','DisassociateFromMasterAccount','UpdateDetector',
                    'DeleteFlowLogs','DisableSecurityHub','DeleteConfigurationRecorder')
ORDER BY eventtime DESC;
-- user agents seen fewer than 5 times in 30 days: often attacker tooling
SELECT useragent, count(*) AS n, array_agg(DISTINCT useridentity.arn) AS who
FROM cloudtrail_logs
WHERE eventtime > to_iso8601(current_timestamp - interval '30' day)
GROUP BY useragent
HAVING count(*) < 5
ORDER BY n ASC;
Checklist

The first 15 minutes of a cloud incident

  1. Declare and assign

    Name an Incident Commander and a scribe. Open a channel and a case (in AWS Security Incident Response, if you use it). Start a timeline.

  2. Preserve before you poke

    Check that CloudTrail is still logging (get-trail-status). Snapshot volumes before you change instances. Don't terminate anything.

  3. Identify the principal

    Is it an access key, a role session or an Identity Center user? lookup-events on AccessKeyId, then trace AssumeRole chains.

  4. Contain identity

    Deactivate keys. Revoke role sessions (a deny on aws:TokenIssueTime). Attach a quarantine SCP to the account if needed.

  5. Contain workloads

    Swap in an isolation security group. Remember that tracked connections persist, so use a NACL if needed. Detach from the ASG and enable termination protection.

  6. Scope the blast radius

    What could this principal reach? Use Access Analyzer, IAM policy simulation and Detective. What did it reach? Check CloudTrail data events.

  7. Hunt for persistence

    New users, keys, roles, trust-policy edits, Lambda functions, EventBridge rules, AMIs or snapshots shared outside the org.

  8. Communicate

    Send a status update every 30 minutes. Bring in legal and comms early if data may be involved.

Lexicon

Glossary

ABAC
Attribute-based access control: permissions decided by matching tags on principals and resources.
Attack sequence
A GuardDuty Extended Threat Detection finding that correlates multiple signals over time into one critical-severity story.
Cedar
AWS's open-source authorization policy language. It is fast, analyzable and deterministic. Used by Verified Permissions and AgentCore Policy.
Confused deputy
A trusted service or third party that is tricked into using its privileges on an attacker's behalf. Countered with ExternalId and the aws:Source* keys.
Data perimeter
A set of preventive guardrails that ensure only trusted identities access trusted resources from expected networks.
Declarative policy
An Organizations policy that sets and locks a service's configuration across accounts, rather than authorizing API calls.
Encryption context
Non-secret key/value pairs bound to a KMS operation as additional authenticated data. They're logged in CloudTrail and can be enforced in key policies.
ML-KEM / ML-DSA
NIST post-quantum algorithms for key establishment (FIPS 203) and digital signatures (FIPS 204).
OCSF
Open Cybersecurity Schema Framework: the normalized schema used by Security Lake and Security Hub.
RCP
Resource control policy: an Organizations policy that sets the maximum permissions on resources, regardless of who is calling.
SSE-C
S3 server-side encryption with customer-provided keys. It is legitimate, but has been abused for ransomware because AWS never stores the key.
