Design philosophy

Why this course feels different

🎯 Mechanisms over menus

We teach how AWS actually decides things: policy evaluation, envelope encryption, GuardDuty's signal correlation. Then the console buttons make sense, and so do the edge cases attackers use.

🏢 Organization-scale by default

Real environments have 40 accounts, not one. Every control is built at the org layer first (SCPs, RCPs, declarative policies, delegated admins), and then tested at the account layer.

⚔️ Offense informs defense

You exploit each weakness yourself, safely in your own sandbox, before you fix it. Once you've escalated through iam:PassRole yourself, you'll spot it in every code review afterwards.

🤖 AI is in scope, both ways

AI agents are a new attack surface (prompt injection, tool abuse) and a new defensive tool (AI investigations, Security Agent pentests). We cover both, with deterministic guardrails.

Program outcomes

After five days, graduates can…

  • Predict the outcome of any AWS authorization request across identity, resource, boundary, session, SCP and RCP layers, and explain why.
  • Design and ship a multi-account guardrail set (SCPs, RCPs, declarative policies) with a CI pipeline that blocks risky policy changes.
  • Build a data perimeter that stops credential use from outside the organization and data movement to untrusted resources.
  • Stand up organization-wide detection and run hypothesis-driven threat hunts in OCSF data using SQL.
  • Write, test and deploy detections as code, and tune GuardDuty and Security Hub to reduce noise.
  • Lock down egress, edge and Kubernetes workloads, and enforce signed, scanned images at admission.
  • Apply KMS key policies, grants and encryption context correctly, and start a post-quantum migration plan.
  • Defend S3 against ransomware (including SSE-C abuse) and recover from it.
  • Attack and then defend an LLM app and an AI agent with Guardrails and Cedar-based AgentCore Policy.
  • Run a credential-compromise and EC2-forensics response end to end, and automate it with Step Functions.

Pairing model

Students work in pairs ("driver" and "navigator") and swap at every lab. On GameDay, two pairs join up to form a team of four.

Instructor-to-student ratio

1 lead instructor plus 1 lab assistant per 12 students. Labs have full solutions behind spoilers, so assistants can focus on why questions instead of typos.

The 15-minute rule

If you've been stuck for 15 minutes, open the hint. Stuck for 25, open the solution and keep going. The boss fight is where you struggle on purpose, not the setup steps.

re:Invent week bonus

If you run the course during or right after re:Invent 2026 (Nov 30 – Dec 4), replace the 08:45 transmission with "what just shipped" and map each launch to that day's modules.

Assessment

How progress is measured

🚩 Flags (50%)

Flags (SKY{...}) are planted inside lab environments. You only find them by actually exploiting or fixing the thing. The site checks each flag's SHA-256 hash in your browser.

🧠 Quizzes (20%)

8–10 scenario questions per day, built to catch "I clicked through it" learning. Every answer comes with an explanation.

🏆 GameDay (30%)

The team score combines flags, a root-cause write-up, and hardening changes that hold up against the instructor's re-attack. Breaking production costs points.

Completion

A student completes the course with 3 of 5 boss badges, at least 60% across the quizzes, and an active role in a GameDay team that submits a root-cause analysis. XP levels are just for fun (and bragging rights).

Lab environment

Your sandbox fortress

Each student (or pair) gets their own AWS Organization, because SCPs, RCPs and declarative policies have to be applied at the org layer. Lab 0 builds it in about 45 minutes. Instructor-led cohorts can pre-provision with the same scripts.

Never use a production organization

Several labs deliberately create vulnerable resources, simulate attacks, and attach deny-all policies. Always use dedicated, disposable sandbox accounts with budget alarms.

Budget

Estimates assume us-east-1, on-demand pricing, and that you tear down at the end of each lab (every lab has a cleanup block). New accounts often get free-tier and free-trial periods for GuardDuty, Security Hub, Inspector and Macie, which lowers costs further.

The #1 way to blow your budget

Leaving the Day 3 Network Firewall or the EKS cluster running overnight. Run the cleanup blocks. The labs/setup/nuke-check.sh script lists the expensive resources still alive.

Before Monday

Pre-work (about 2 hours)

  1. Complete Lab 0

    Set up your sandbox organization, CloudShell tooling and budget alarms. Go to Lab 0 →

  2. Refresh the IAM policy grammar

    Read the AWS docs pages "Policy evaluation logic" and "IAM JSON policy elements reference". Have Condition operators fresh in your head.

  3. Skim MITRE ATT&CK for Cloud (IaaS)

    Know the tactic names. We use them on Day 2 and Day 5.

  4. Enable Bedrock model access

    In your skyfortress-dev account, enable access to an Anthropic Claude model in Amazon Bedrock (Day 4 needs it). Approval is usually instant, but do it early.

  5. Read the OWASP Top 10 for LLM Applications (2025)

    At least LLM01 (prompt injection) and LLM06 (excessive agency).

For instructors

Facilitation guide

📦 What's in the repo

  • dayN.html: student-facing content
  • labs/dayN/: templates, scripts and policies
  • instructor/: flag answer keys, solutions, timing notes. Gitignored, so it is never published to Pages. Share it privately.

⏱ Pacing levers

  • Running long? Every lab's stretch goal can be skipped.
  • Running short? Boss fights can expand to 60 minutes.
  • Day 3 is the heaviest day. Pre-deploy the EKS cluster at lunch.

🎭 Running the story

  • Read the morning "transmission" aloud. Doing voices is optional but encouraged.
  • Put the leaderboard on a screen at the 16:50 quiz block.
  • Hand out physical stickers that match the badges.

🧯 When things break

  • Service-quota or Region issues: every lab lists a fallback.
  • Bedrock access delays: Day 4 labs include a local fallback path.
  • Keep one pre-built "golden" sandbox for demos.
